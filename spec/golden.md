# Spec: the golden test vector corpus

Design doc reference: section 8 (a golden test corpus generated by the
reference, checked in CI at the bit level), section 12 Phase 0 exit
criterion. Implemented in `src/gittins_reference/golden.py` (PR 10);
corpus at `spec/golden.json`.

## What it is

`spec/golden.json` is a machine-readable corpus of (input → expected
output) vectors produced by the reference implementation. Every other
implementation — the Rust core, each language binding — must reproduce it
**bit for bit** in CI. Matching the `episode` section end to end is the
Phase 0 exit criterion for an independent `decide`/`learn` implementation.

Regenerate with `uv run python -m gittins_reference.golden`.
`tests/test_golden.py` asserts the checked-in file equals regeneration
exactly, so any semantic drift in the reference fails CI and shows up as a
reviewable diff of vectors. A *deliberate* semantics change therefore has
a defined workflow: change the code, regenerate, and review the vector
diff like code.

## Sections

| section | covers |
|---|---|
| `rng` | key derivation (incl. the length-prefix boundary cases and non-ASCII), u64/unit streams, a 2^32 counter |
| `model` | update history → the sums after every update, and a prediction |
| `exploration` | inverse-gap distribution, floored distribution, sampled indices |
| `encoding` | tokenization, pair hashes, full hashed vectors at bits 4 and 6 |
| `episode` | the end-to-end acceptance scenario (below) |

The `episode` section is one agent making hash-encoded decisions with
out-of-order (deferred) rewards, one censored decision, and one
never-resolved decision expired by a sweep at its exact horizon — the full
event stream (every decision record, every resolution, in order), the
final state, and predictions per (segment, arm). Training is
order-dependent (per-update forgetting), so the resolution sequence *is*
part of the contract. All three resolution kinds occur; no decision is
left open.

## Serialization contract

- Floats are JSON numbers in Python's shortest round-trip repr: parse to
  IEEE-754 doubles and compare **bitwise**, not with tolerances.
- Hashes and RNG outputs are unsigned 64-bit integers as JSON numbers.
- The corpus contains no NaN or Infinity (standard JSON only); scenarios
  needing `forgetting = 1.0` (never forget) live in the pytest suites.
- The file is ASCII (JSON `\uXXXX` escapes), LF line endings, enforced by
  `.gitattributes` — it is compared as exact text on every platform.

## CI

`.github/workflows/ci.yml` runs the full pytest suite on every pull
request and push to main, on Ubuntu across Python 3.10–3.14. Because the
suite pins outputs at the bit level and regenerates the corpus, every
matrix leg is a bit-identity check (R6). macOS/Windows legs are deferred
for cost; cross-OS bit-identity remains a release gate and returns to the
matrix when the compiled core lands. Planned growth: the simulation
battery with regret baselines (section 10), the Rust core and every
binding validated against this corpus, WASM.
